# Portfolio and CMS QA — 18 October 2026

## Verdict

Remediation update (23 October): the first fix batch addresses B01–B06, B09 and B12, plus part of B07/B16. See PROJECT_RECORD.md for checks and limits. Preserve the findings below as the historical audit; remaining issues are not marked resolved by this note.

The root app builds and its routes load, but the CMS is not ready to promise reliable no-code production publishing. Highest priorities are durable production mutations, media preservation, server validation and draft protection. This QA pass reports findings; it does not implement fixes.

Tested root checkout: Next.js 15.5.27, current local source following commit 4b93273. Local development at port 3000; separate production-mode server at port 3002 with a disposable process-only admin password. No real password recorded.

## Results and coverage

- Lint and TypeScript passed. Production build passed, including static generation.
- 12 main/admin page routes and five content APIs returned 200. All 17 existing item detail routes returned 200. A nonexistent page returned 404.
- Production: unauthenticated admin, upload, AI intake, diagnostics and page writes returned 401. Authenticated dashboard/item reads returned 200. Public Home content and featured API remained available without authentication.
- Invalid contact input returned 400. Local health reports SMTP and Turnstile unconfigured; no real email was sent.

- Disposable item tests: rename, category move and blank-field submission. Fixtures removed afterward; existing portfolio records untouched. Empty fixture media directories may remain, with no tracked content changes.
- Production cache test: created a disposable JSON record after build. Detail URL returned 200, while the prebuilt Projects listing omitted it. Fixture removed afterward.
- Checked installed PDF/DOCX extraction APIs locally without contacting an AI provider.
- npm audit: 20 flagged dependency entries (15 high, five moderate, zero critical), including direct and transitive, runtime and development dependencies. These counts are not 20 proven exploitable application vulnerabilities. Next.js and PostCSS were not flagged in this audit.

## Deployment and configuration risks

- Production upload silently chooses filesystem mode if any GitHub setting is absent. It should fail with clear configuration feedback rather than attempting nondurable saves (`shouldUseGitHubPr` in upload route).
- Local SMTP is missing required settings and Turnstile is absent. This establishes local readiness only; production Vercel values were not inspected.
- npm audit flags runtime nodemailer/mammoth/XML dependencies and development tooling. Review advisory reachability, upgrade compatible patches and rerun build; avoid blanket forced upgrades. The Next.js/PostCSS security update does not resolve every dependency.
- Public email HTML interpolates name/message without escaping. Owner inbox rendering can interpret submitted markup. Escape before generating HTML; no email injection test sent.
- Development bypass of admin login when no ADMIN_PASSWORD is set is intentional. Production was tested with a disposable process password; no live Vercel account/configuration was changed.
- Content errors are swallowed in `getAllItems`: one malformed JSON makes the whole category return an empty list. Validate records and surface per-record diagnostics instead of silently hiding the entire category.
- Requests lack an application-level aggregate upload cap and collision handling for filenames/slugs. Duplicate title/date saves can overwrite an existing item. Harden before opening broader admin access.

## Requirements still planned (opportunities, not regressions)

1. Durable content/media storage and explicit Draft -> Preview -> Publish -> Published states; Git PR mode must remain visibly pending until deployed.
2. Ordinary project body/content-block editor with galleries, captions, maps, charts, cover selection and attachment removal.
3. Image upload/library chooser for Home and Contact; image paths should not be a routine owner task.
4. Section show/hide and ordering, navigation/menu editor, list-page introductions and metadata settings.
5. Automatic published-project/training counts and experience calculation, excluding test/draft records. Current Home numbers are fixed strings and include the typo “Artical Published”.
6. Search, year/tag filtering, bulk archive and clear content classifications for Projects/Achievements/ECA.
7. Version history/restore, draft autosave, edit conflict protection and publication audit trail.
8. Configured email status in the dashboard; inquiry inbox and analytics only if persistent storage and requirements are agreed.
9. Repeatable integration checks for edit/media preservation, invalid inputs, authorization, publishing state and route rendering; responsive/keyboard regression checks.

## Recommended work order

1. Protect content: stable URLs, preserve assets/body, category move handling, server validation and fail-closed production storage configuration.
2. Repair PDF/DOCX intake and review vulnerable runtime dependencies.
3. Unify durable create/edit/delete/publish and cache invalidation; add drafts/history/conflict handling.
4. Prevent unsaved-navigation loss; fix missing assets/CTA and accessibility defects.
5. Migrate dedicated project pages; finish page section/list/media controls and metadata settings.

## Limits

No live Vercel deployment, real GitHub PR creation/merge, SMTP delivery, paid AI generation, destructive portfolio deletion or full accessibility/performance audit was performed. Source-inspected risks are explicitly distinguished from reproduced defects. Successful HTTP responses alone do not establish UI correctness. Disposable fixture updates were cleaned up; this report and the project-record update are the intended repository changes.
